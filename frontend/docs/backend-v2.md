# The website on backend-v2

The parent website talks to backend-v2 (`backend-v2/`), the TypeScript backend built from the technical proposal. This page is the contract between the two: every call the site makes, the shapes that come back, how the site maps backend-v2's model onto its screens, and the toy protocol a Buddy in the browser speaks.

`src/lib/api.js` is the only module that calls the backend; `src/lib/buddy.js` holds the mapping rules; `src/dashboard/data.jsx` loads what the dashboard shows.

## Where it lives

The site calls everything under `/v2`, same-origin, so backend-v2 needs no CORS.

| Site path | Production (nginx) | Development (`vite.config.js`) |
|---|---|---|
| `/v2/...` | Parent API `127.0.0.1:3610/v1/...` | `http://localhost:3100/v1/...` |
| `/v2/device` (WebSocket) | voice service `127.0.0.1:3611/v1/device` | `http://localhost:3101/v1/device` |

Local development needs no database server: `npm run dev:lite` in `backend-v2/` runs the API, the voice service and the worker on PGlite (kept in `backend-v2/.pglite/`, delete it to start over), with `GATEWAY=fake` stand-ins for OpenAI and ElevenLabs unless keys are set. Then `npm run dev` in `frontend/`.

## Errors and sessions

Errors are problem details: `{ type: "/problems/<code>", title, status, errors?: [{ field, code }] }`. `ApiError` exposes `status`, `code` in snake case (`email-taken` becomes `email_taken`, so the dictionaries name messages `err_<code>`), `fields` (the `errors` list) and `retryAfter` (the `Retry-After` header in whole seconds, or null).

Codes the site meets: `invalid_request` (400, see `fields`), `unauthorized` (401), `invalid_credentials` (401, login), `email_taken` (409), `rate_limited` (429), `not_found` (404), `invalid_claim` (404, a wrong or used claim code), `toy_in_family` (409, a card the family already holds, for another child or asleep: unpair it first), `child_has_toy` (409), `web_toy_limit` (409), `web_toy_off` (403), `toy_not_active` (409), `toy_held` (409, a toy staff disabled), `payments_disabled` (403), `purchase_not_pending` (409), `consent_required` (409), `stale_write` (412), `precondition_required` (428), `buddy_exists` (409), `bad_entry` (400, a speech entry whose heard and meant words are the same), `network_error`.

Budgets: every 429 (`rate_limited`) carries `Retry-After` in whole seconds (at least 1). Signed-in calls: 60 a minute per parent (bursts of 120), within which 20 purchases a minute, 10 pairings an hour (claiming a toy and making a web Buddy count together, so a refused one can wait about 6 minutes) and 10 web Buddies made a day per family (the wait runs until the oldest of the day's is a day old, up to 24 hours). Per IP: 10 sign-ins a minute (bursts of 20), 5 sign-ups an hour (a refused sign-up can wait about 12 minutes), 60 token refreshes or sign-outs a minute, 60 credit pack reads a minute. Because these refill at such different speeds, the site words the wait by its size (`waitWords` in `lib/format.js`, which `useErrorText` uses, so the sign-in page, toasts and the dashboard's first-load card all word it alike): under 90 seconds in seconds, under 90 minutes in minutes, otherwise in hours, always rounded up; with no usable header, or a wait of one second, it just asks to wait a little.

The dashboard stays inside the parent budget. A family load (`reload` in `data.jsx`, after an action and every 30 seconds while the page is visible) costs 5 calls plus 3 per child (the Buddy, the alerts and the week's usage); the credit packs count against the public budget, and voices and characters load once per page. A turn on the Talk screen does not reload the family: `refreshAfterTurn(result)` refreshes only the wallet and the turns (the week chart catches up at the next family load), only for an `answered` turn, at most once every 10 seconds and a moment after the last answer (the toy's `turn_done` arrives before the voice service writes the turn and its debit).

Access tokens last 15 minutes and live in memory; the refresh token is in localStorage under `lb-web-refresh-v2`. Any 401 on a signed-in call refreshes once and retries; refreshes are shared so a rotated token is never presented twice (that ends every session). A refresh token the site kept for the first backend (under `lb-web-refresh`) stays valid there, and nginx still sends same-origin `/api/` to it, so the first time `api.js` loads it removes that token and revokes it with `POST /api/auth/logout` (fire and forget, `keepalive`).

## Calls

**Sign-in.** `POST /auth/register { email, password (8+), family_name, display_name? }` 201, and `POST /auth/login { email, password }` 200, both `{ access_token, refresh_token, token_type, expires_in, parent: { id, email, display_name, role }, family: { id, name } }`. Wrong password and unknown email are the same 401. `POST /auth/refresh { refresh_token }`, `POST /auth/logout { refresh_token }`. Every new family gets welcome credits (1000 at the demo stage).

**Account.** `GET /me` is `{ parent, family: { id, name, country, created_at }, children: [{ id, name, nickname }], web_toy, payments, speak_first }`: `web_toy` says whether a Buddy can live in the browser, `payments` is `demo` or `disabled` (buying answers 403 `payments_disabled` when disabled; production is disabled), and `speak_first` says whether the voice service lets Buddy greet first at all. It is false in production, and while it is false a child's "Buddy speaks first" control (`speak_first` in controls) has no effect. `PATCH /me { display_name }`, `PATCH /family { name }`. `GET/POST /consents`, `DELETE /consents/:kind`: learning needs a `learning` consent before `PATCH /children/:id { learning_enabled: true }` succeeds (409 `consent_required` otherwise), and withdrawing it switches learning off for every child.

**Children.** `GET /children` `{ data }`, `POST /children { name, nickname?, birth_date? (YYYY-MM-DD), languages? (['vi'] | ['en'] | ['vi','en']), time_zone? (IANA, send the browser's), city? }` 201 child, `PATCH /children/:id` (same fields plus `learning_enabled`), `DELETE /children/:id` (frees its toys). A child: `{ id, name, nickname, birth_date, languages, time_zone, city, learning_enabled, created_at }`.

**Buddy.** One per child.
- `GET /characters` `{ data: [{ slug, name, who, themes, voices: { vi, en } }] }`: Bo, Pip, Luna. `voices` is the character's own voice per language (a voice id or null), the same ids as `character_voices` on a Buddy, so the voice step can show it before the child has a Buddy.
- `GET /questionnaire` (Accept-Language vi or en) and `POST /children/:id/questionnaire { answers: [{ question, answer, by }] }` 201 `{ questionnaire_id, match: { character: { slug, name }, score, dials }, alternatives }`. Required answers: `friend_energy` (bouncy|calm) and `friend_style` (silly|curious|gentle); `role` (friend|sibling|parent_figure|teacher) and `language` (vi|en|bilingual) set the Buddy's role and language; the others (`together`, `favourite_place`, `favourite_animal`, `favourite_colour`, `routines`, `avoid_topics`) are optional. The site derives `friend_energy` from the personality's E/I and `friend_style` from N (curious), F (gentle) or else silly.
- `POST /children/:id/buddy { questionnaire_id, character_slug }` 201 creates it (409 `buddy_exists` if the child has one). `POST /children/:id/buddy/change { questionnaire_id, character_slug, confirm: true }` swaps the character, which starts a new friendship (the child's memories stay).
- `GET /children/:id/buddy` (404 until set up; `api.buddy` gives null): `{ id, character_slug, character_name, role, language_mode, dials: { energy, playfulness, curiosity, warmth, structure }, relationship_stage, met_on, personality, voice_id, character_voices: { vi, en }, created_at, etag }`.
- `PATCH /children/:id/buddy` with `If-Match: <etag>`: any of `role`, `language_mode`, `dials`, `personality` (`ENFP`... or null), `voice_id` (null = the character's own voice). A personality sets the dials. Buddy speaks out loud in one language (`speechLanguage`): its own, or for a bilingual Buddy the child's first language (`languages[0]`), and a picked voice must speak that one (400, field `voice_id`, code `language`); switching language drops a voice that no longer fits. 412 `stale_write` when someone else changed it.
- `GET /voices` `{ data: [{ id, name, language }] }`. Samples: `/voice-samples/<id>.wav`.

**Toys.** `GET /devices` `{ data: [{ id, serial, hardware_rev ('web' for a Buddy in the browser), status (active|disabled|provisioned|revoked), disabled_by (parent|staff|null), child_id, firmware_version, last_seen_at, claimed_at, online }] }`. `POST /devices/claim { claim_code: "ABCD-EFGH", child_id }` (case and dashes do not matter; a wrong or already used code is the same 404 `invalid_claim`). `POST /devices/web { child_id }` 201 makes a Buddy that lives in the browser (`web_toy` must be on, at most 3 per family, one awake toy per child). `POST /devices/:id/credential` `{ device_id, secret }` (base64url) for a web Buddy of this family while it is awake. `POST /devices/:id/pause` and `/resume` (a parent wakes only what a parent paused). `POST /devices/:id/unpair`: a physical toy can be claimed again with its code; a web Buddy is gone for good.

**Credits.** `GET /credit-packs` (no token) `{ packs: [{ id, name, credits, price_amount, currency }] }`. `GET /wallet?limit=` `{ balance, ledger: [{ id, kind (grant|purchase|debit|refund), delta, reason ('welcome', 'pack:<id>', 'turn'), child_id, turn_id, purchase_id, created_at }] }`, newest first. `POST /purchases { pack_id, idempotency_key }` 201 `{ purchase }`, `POST /purchases/:id/demo-pay { outcome: success|decline }` `{ purchase, balance }`, `GET /purchases`. One answered turn costs one credit; Buddy greeting first or asking again costs nothing. With no credits the toy plays its napping clip, so the site shows the empty wallet itself.

**Activity.** `GET /turns?limit=&child_id=` `{ data: [{ id, child_id, created_at, face, turn_type, language, charged }] }`, newest first, the last 30 days, never the words (`limit` 1 to 500, 100 by default). The site's lists take the family's newest 200; a child picked on the Activity screen gets their own 200 (`child_id`), since a chatty sibling can fill the family's. `GET /children/:id/usage?from=&to=` `{ data: [{ day, turns, talk_minutes }] }`, one row per day the child talked, on the child's local date (`YYYY-MM-DD`; `from` and `to` default to the last 30 days). The voice service adds to it on every turn it records (a greeting Buddy starts itself too), and forgetting a child's memories keeps it. The home chart asks each child for the last seven days (`weekRange` in `lib/stats.js`) and adds the children up per day (`weekFromUsage`), so it holds however many turns the family had.

**What Buddy knows.** Per child: `GET /memory/summary` (the digest Buddy keeps: `name, nickname, ageYears, passions, likes, dislikes, fears, strengths, people, topicsToAvoid`, plus `counts { people, facts, events }` and `learning_enabled`); `GET /people?kind=` and `GET/PATCH/DELETE /people/:id` (`{ id, display_name, kind, relation, details, aliases, closeness, mentions, first_mentioned_at, last_mentioned_at, etag }`; PATCH `{ display_name, kind, relation, details }` with If-Match); `GET/POST /facts?category=` and `PATCH/DELETE /facts/:id` (`{ id, category, statement, person_id, source (child|parent|setup|inferred), confidence, reality, sensitivity, mentions, first_seen_at, last_seen_at, etag }`; a parent's fact or fix wins); `GET /events`, `PATCH/DELETE /events/:id` (`{ id, kind (routine|upcoming|milestone), description, starts_on, status, etag }`); `GET /relationship` (nicknames, inside jokes, rituals, promises); `GET /traits`, `DELETE /traits/:name`; `GET /words` (words being learned); `GET/POST /speech`, `DELETE /speech/:id` (the child's own way of saying things); `DELETE /memory` forgets everything Buddy learned (alerts, digests, usage and the toy stay). Lists page with `{ data, next_cursor }` and `?cursor=`.

**Safety.** `GET /children/:id/alerts` (concern and urgent only) `{ data: [{ id, severity (concern|urgent), category, excerpt, created_at, acknowledged_at }], next_cursor }`: the excerpt is the only place a parent sees the child's words. `POST .../alerts/:id/acknowledge`, `DELETE .../alerts/:id`.

**Weekly digests.** `GET /children/:id/digests` `{ data: [{ id, week_start, content: { highlights, new_interests, mood_trend, people, conversation_starters, turns, minutes }, created_at }], next_cursor }`; `GET .../digests/:week_start`.

**Controls.** `GET /children/:id/controls` `{ daily_limit_min, quiet_start, quiet_end, bedtime, topics_to_avoid, mood_pin, surprise_play, speak_first, updated_at, etag }` and `PUT` the whole object (without `updated_at` and `etag`) with If-Match. `GET/POST /nudges { content, use_after?, expires_at? }` (something a parent wants Buddy to bring up), `DELETE /nudges/:id`. `GET/PUT /goals { focuses: [...] }` (up to 5).

## How the site maps backend-v2's model

- A toy belongs to a child, and a child has one Buddy, so a toy's name is its child's Buddy's (`toyView` in `lib/buddy.js`). A child has at most one awake toy.
- The Buddy's name is its character's name. Every Buddy is drawn as Miu, the talking kitten: the characters differ in name, personality and voice, not in look.
- Roles are `friend`, `sibling`, `parent_figure`, `teacher` (Vietnamese pronouns tớ/cậu, anh/em, cô/con, cô/con).
- Language is `vi`, `en` or `bilingual` (answers in the language the child used).
- Personality is one of the 16 types (`lib/personality.js`, the 12-question quiz or the grid); it sets the dials.
- Voice: the picker lists the voices of the one language Buddy speaks out loud (`speechLanguage` in `lib/buddy.js`: a bilingual Buddy answers in the child's language but always with a voice of the child's first language); the character's own voice is the default (picking it stores null).
- Learning and the mood pin belong to the child (learning needs consent; the mood pin lives in controls), not to a toy.

## A Buddy in the browser: the toy protocol

1. `POST /v2/devices/:id/credential` gives `{ device_id, secret }` (base64url of 32 bytes). Keep it in memory for this page only; forget it on sign-out.
2. Open `wss://<host>/v2/device` (`deviceSocketUrl()`). The server sends `{ type: "challenge", nonce, server_time }`.
3. Reply `{ type: "hello", device_id, protocol: 1, firmware: "web-1", battery: null, clips_version: null, signature }` where `signature` is base64url(HMAC-SHA256(secret, `${nonce}.${device_id}.${server_time}`)). The server's own time is signed, so the browser clock does not matter.
4. The server answers `{ type: "ready", claimed, language_mode, quiet_hours, limit_reached, clips_version, ping_interval_s, codec: "pcm16", sample_rate: 16000, frame_ms: 20 }`. It pings the socket; browsers answer pings themselves.
5. A turn: send `{ type: "turn_start", turn_id }` (1 to 64 of `A-Za-z0-9_-`), then binary frames, then `{ type: "turn_end", turn_id, reason: "tap"|"silence"|"cap" }`. `{ type: "cancel", turn_id }` stops one. Audio may follow `turn_start` at once.
6. Frames both ways: a 4-byte header (byte 0 version 1, byte 1 direction 0 up or 1 down, bytes 2-3 sequence number big-endian) and then raw PCM16 little-endian mono at 16 kHz, 640 bytes (20 ms) per uplink frame. Downlink frames carry Buddy's voice the same way.
7. The server sends `{ type: "face", emotion, phase }` (listening, thinking, speaking), downlink audio, `{ type: "audio_end" }` when an answer has been spoken, `{ type: "play_clip", clip }` (`napping` for any refusal: no Buddy, no credits, paused; `sleepy` for quiet hours or the daily limit; `didnt_catch` when nothing was heard or the turn failed), `{ type: "buddy_turn" }` when Buddy speaks first (never while `me.speak_first` is false), `{ type: "error", code }`, and always `{ type: "turn_done", turn_id, result }` with `answered`, `no_speech`, `failed`, `cancelled` or `blocked`. That includes a tap the voice service fails to start (a database or recogniser failure): it gets `play_clip` `didnt_catch`, then `turn_done` `failed`, so the toy never waits on a turn that will not come. The page still does not stake its liveness on `turn_done` (`watch` and `stallPlan` in `src/talk/machine.js`): a turn with nothing back 30 seconds after `turn_end` (or `buddy_turn`), or 15 seconds after Buddy's last face, frame, clip or `audio_end` (never before the voice already queued has played, plus 3 seconds), is cancelled with one line on the screen, and the page listens again, or reconnects when the socket has said nothing since the turn last moved.
8. Close codes: 4001 sign-in failed, 4003 paused or revoked, 4008 protocol, 4009 replaced by a newer connection, 4029 too many.
